# Migration Guide: 1.3.5

This release adds **comic (DIVINA) reading** as a first-class profile alongside EPUB, WebPub, and audio. The sections below also document the **1.3.0** changes (audio support and the `StatefulReaderWrapper` provider model) so you can upgrade from **1.2.x** to **1.3.5** in one pass. If you are already on **1.3.0**, read [New: Comic reader support](#new-comic-reader-support) and ensure `usePublication` / `StatefulReaderWrapper` types include `"comic"`.

---

## New: Comic reader support

`usePublication` and `StatefulReaderWrapper` detect and handle the `"comic"` profile for Web Publications that declare the DIVINA profile or that expose an image-only `readingOrder` (see [Profile detection](#comic-profile-detection)).

```tsx
const { publication, profile, localDataKey } = usePublication({ url });
// profile may now be "epub" | "webPub" | "audio" | "comic" | null

<StatefulReaderWrapper
  profile={ profile }
  publication={ publication }
  localDataKey={ localDataKey }
/>
```

### Plugins

`ReaderPlugins` accepts a `comic` factory alongside `epub`, `webPub`, and `audio`. For comics, use the same `createDefaultPlugin` as for EPUB/WebPub — it registers the comic-specific settings (reading mode, tap zones, progress bar, and so on) when those profiles are active:

```tsx
import { createDefaultPlugin, createAudioDefaultPlugin } from "@edrlab/thorium-web/reader";

<StatefulReaderWrapper
  profile={ profile }
  publication={ publication }
  localDataKey={ localDataKey }
  plugins={{
    epub: () => [createDefaultPlugin()],
    webPub: () => [createDefaultPlugin()],
    comic: () => [createDefaultPlugin()],
    audio: () => [createAudioDefaultPlugin()]
  }}
/>
```

The wrapper resolves only the factory matching the active profile — unused factories are never called.

### Preferences

For `"comic"`, `StatefulReaderWrapper` uses the same EPUB/WebPub preferences path as `"epub"` and `"webPub"`: `ThPreferencesProvider` with `createPreferences` (not `createAudioPreferences`).

```tsx
import { createPreferences } from "@edrlab/thorium-web/reader";

<StatefulReaderWrapper
  profile="comic"
  publication={ publication }
  localDataKey={ localDataKey }
  preferences={{
    initialPreferences: createPreferences({ /* ... */ }),
    adapter: myAdapter  // optional
  }}
/>
```

### Using `StatefulComicReader` directly

If you mount `StatefulComicReader` from `@edrlab/thorium-web/comic` instead of `StatefulReaderWrapper`, you must supply the same outer providers as for EPUB/WebPub: `ThStoreProvider`, `ThPreferencesProvider`, and `ThI18nProvider`. Prefer `StatefulReaderWrapper` when possible so preferences and i18n stay consistent with the rest of the 1.3.x reader stack.

Import the comic package styles when you use the comic entry point (for example in your app shell or layout):

```tsx
import "@edrlab/thorium-web/comic/styles";
```

When you only use `StatefulReaderWrapper` from `@edrlab/thorium-web/reader`, follow the existing reader styling guidance and import `@edrlab/thorium-web/reader/styles` as before.

### Comic profile detection

- **Declared DIVINA:** `metadata.conformsTo` includes the Readium DIVINA profile URI (`https://readium.org/webpub-manifest/profiles/divina`, available in code as `Profile.DIVINA` from `@readium/shared`).
- **Image-only fallback:** if there is no `conformsTo`, a manifest whose `readingOrder` items all have an `image/*` media type is treated as a comic.

## New: Audio player support (from 1.3.0)

`StatefulReaderWrapper` and `usePublication` detect and handle the `"audio"` profile automatically. No changes are required to existing EPUB or WebPub integrations.

```tsx
const { publication, profile, localDataKey } = usePublication({ url });
// profile may now be "epub" | "webPub" | "audio" | "comic" | null

<StatefulReaderWrapper
  profile={ profile }
  publication={ publication }
  localDataKey={ localDataKey }
/>
```

### Plugins

`ReaderPlugins` accepts an `audio` factory alongside `epub`, `webPub`, and `comic`. Use `createAudioDefaultPlugin` to get the built-in audio plugin set, the same way `createDefaultPlugin` works for EPUB and WebPub:

```tsx
import { createDefaultPlugin, createAudioDefaultPlugin } from "@edrlab/thorium-web/reader";

<StatefulReaderWrapper
  profile={ profile }
  publication={ publication }
  localDataKey={ localDataKey }
  plugins={{
    epub: () => [createDefaultPlugin()],
    audio: () => [createAudioDefaultPlugin()]
  }}
/>
```

The wrapper resolves only the factory matching the active profile — unused factories are never called.

### Preferences

`StatefulReaderWrapper` accepts a `preferences` prop to pass initial preferences or a custom adapter to the underlying provider. The shape is profile-specific:

```tsx
import { createAudioPreferences } from "@edrlab/thorium-web/audio";
import { createPreferences } from "@edrlab/thorium-web/reader";

// Audio
<StatefulReaderWrapper
  profile="audio"
  publication={ publication }
  localDataKey={ localDataKey }
  preferences={{
    initialPreferences: createAudioPreferences({ /* ... */ }),
    adapter: myAudioAdapter  // optional
  }}
/>

// EPUB / WebPub / Comic
<StatefulReaderWrapper
  profile={ profile }
  publication={ publication }
  localDataKey={ localDataKey }
  preferences={{
    initialPreferences: createPreferences({ /* ... */ }),
    adapter: myAdapter  // optional
  }}
/>
```

### Using `StatefulPlayer` directly

If you use `StatefulPlayer` from `@edrlab/thorium-web/audio` instead of `StatefulReaderWrapper`, you are responsible for wrapping it with the required providers. `ThAudioPreferencesProvider` is separate from `ThPreferencesProvider` — do not use the EPUB/WebPub/comic one for audio.

```tsx
import {
  StatefulPlayer,
  ThStoreProvider,
  ThAudioPreferencesProvider,
  ThI18nProvider,
  createAudioPreferences
} from "@edrlab/thorium-web/audio";

const myPreferences = createAudioPreferences({ /* ... */ });

<ThStoreProvider>
  <ThAudioPreferencesProvider initialPreferences={ myPreferences }>
    <ThI18nProvider>
      <StatefulPlayer
        publication={ publication }
        localDataKey={ localDataKey }
      />
    </ThI18nProvider>
  </ThAudioPreferencesProvider>
</ThStoreProvider>
```

> [!CAUTION]
> All components from `@edrlab/thorium-web/audio` must use the providers from that same path. Using providers from `@edrlab/thorium-web/reader` or `@edrlab/thorium-web/epub` will create a separate context that the audio components cannot access.

See the [Audio package documentation](../packages/Audio/ReadMe.md) for the full guide.

## Breaking: `StatefulReaderWrapper` now manages `ThPreferencesProvider` and `ThI18nProvider` internally (from 1.3.0)

`StatefulReaderWrapper` now mounts the appropriate preferences provider (`ThPreferencesProvider` for EPUB/WebPub/comic, `ThAudioPreferencesProvider` for audio) and `ThI18nProvider` internally. **Remove these from your outer component tree.** Keeping them will result in nested duplicate providers.

**Before (1.2.0):**
```tsx
<ThStoreProvider>
  <ThPreferencesProvider initialPreferences={ myPreferences }>
    <ThI18nProvider>
      <StatefulReaderWrapper
        profile={ profile }
        publication={ publication }
        localDataKey={ localDataKey }
      />
    </ThI18nProvider>
  </ThPreferencesProvider>
</ThStoreProvider>
```

**After (1.3.x):**
```tsx
<ThStoreProvider>
  <StatefulReaderWrapper
    profile={ profile }
    publication={ publication }
    localDataKey={ localDataKey }
    preferences={{ initialPreferences: myPreferences }}
  />
</ThStoreProvider>
```

## New: `useTheming` additions (from 1.3.0)

`useTheming` has been extended with cover-based automatic theme generation. All new properties are optional.

**New input props:**
- `coverUrl`: cover image URL to extract a theme from
- `autoThemeSource`: `"cover"` or `"system"`
- `onCoverThemeGenerated`: callback fired when cover theme tokens are ready

**New return values:**
- `coverThemeTokens`: the generated `ThemeTokens`, or `null` if not yet ready
- `themeResolved`: `false` while cover theme extraction is in progress — use this to defer rendering

## New: `ThSliderWithPresets` and `StatefulSliderWithPresets` (from 1.3.0)

A new core component combining a slider with a preset radio group, used internally by the audio player and available for custom integrations.

```tsx
import { ThSliderWithPresets } from "@edrlab/thorium-web/core/components";
```
