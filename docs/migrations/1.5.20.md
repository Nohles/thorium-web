# Migration Guide: 1.5.20

This release syncs the fork with upstream Thorium Web 1.5.7, updates the
Readium Web toolchain, and consolidates host-owned reader interactions.

## Required dependency updates

Applications should align their direct Readium dependencies with Thorium Web:

```json
{
  "@readium/css": "2.0.5",
  "@readium/navigator": "2.8.0",
  "@readium/navigator-html-injectables": "2.6.3",
  "@readium/shared": "2.4.0"
}
```

Keeping older direct dependencies can create multiple `Locator`, `Timeline`,
and navigator module instances. This is especially risky for applications that
create locators themselves and pass them to `useNavigator()`.

Locales are now vendored in the package. Applications that serve Thorium
locales from their own public directory should refresh those files from
`public/locales` when upgrading.

## Reader interactions

EPUB and WebPub now share one interaction contract through
`ReaderInteractionProps`:

```tsx
<StatefulReaderWrapper
  decorations={decorations}
  onTextSelected={handleTextSelected}
  onContextMenu={handleContextMenu}
  onDecorationActivated={handleDecorationActivated}
  {...readerProps}
/>
```

Selection events now include a Readium `Locator` when available, along with
host-document and frame-relative coordinates. Decoration activation events can
include the decoration locator and `extras`.

Decorations can opt into `"tap"`, `"click"`, or `"both"` activation. The
default is `"both"`. Integrations should set this explicitly when preserving a
specific interaction model matters.

The older `dictionary` prop remains available through a compatibility adapter
and keeps its historical click-only activation, but it is deprecated. New
integrations should use `ReaderInteractionProps` directly.

## Timeline and publication state

The deprecated `useTimeline` hook and `publication.unstableTimeline` state were
replaced by:

- `usePublicationProgress` and `publication.progress`
- `publication.toc`
- `publication.adjacentTimelineItems`
- the navigator's Readium `Timeline` API

Applications that only use `StatefulReaderWrapper` do not need to migrate this
state directly. Custom reader chrome that reads Thorium's Redux store must use
the new fields.

Stored position lists are now serialized in Redux and deserialized at the
navigator boundary. This avoids persisting class instances and fixes cold-load
position restoration for WebPub and audio publications.

## Theme persistence

The generated cover theme moved from `state.theming.coverTheme` to transient
`state.publication.coverTheme`. Applications that persist the theming slice
should remove any legacy `coverTheme` value during hydration and avoid writing
it back.

Automatic themes now fall back to the system color scheme when a publication
has no usable cover.

## Provider hierarchy

`StatefulReaderWrapper` continues to manage the profile-specific preferences
provider and `ThI18nProvider` internally. Do not wrap it in duplicate instances.
The Redux-backed global preferences provider still belongs outside the wrapper:

```tsx
<ThStoreProvider>
  <StatefulGlobalPreferencesProvider>
    <StatefulReaderWrapper {...readerProps} />
  </StatefulGlobalPreferencesProvider>
</ThStoreProvider>
```
